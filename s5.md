# Section 5 - User Interface & User Experience

## 5.1 Overview

The User Interface (UI) exists to communicate essential gameplay information while remaining simple, readable and lightweight.

Unlike traditional games, the UI itself is part of the gameplay.

Players can choose to disable portions of the HUD in exchange for gameplay advantages.

Because of this, every UI element must remain modular and independently toggleable.

---

# 5.2 Design Principles

The interface should follow four core principles.

### Clarity

Information should be readable at a glance.

The player should never need to search for important information.

---

### Minimalism

Only information useful during gameplay should remain visible.

Decorative UI should be avoided.

---

### Consistency

Every menu should follow the same visual language.

* Pixel-art buttons
* Consistent fonts
* Simple animations
* High contrast

---

### Responsiveness

Every interaction should provide immediate feedback through:

* sound effects;
* button animation;
* highlight effects;
* hover states.

Menus should feel responsive rather than static.

---

# 5.3 Main Menu

The game starts on the Main Menu.

Options:

* Play
* Settings
* Credits
* Exit

Background:

Animated gameplay scene or pixel-art illustration.

Music begins playing here.

---

# 5.4 In-Game HUD

The HUD displays gameplay information.

Current planned elements:

### Player HP

Displayed directly beneath the player.

Green horizontal bar.

Updates continuously.

---

### Player XP

Displayed beneath the HP bar.

Yellow horizontal bar.

Fills until level-up.

---

### Inventory

Located in the upper-left corner.

Contains four slots.

Slot 1

Melee weapon.

---

Slot 2

Pistol.

---

Slot 3

Current special weapon.

Displays:

* icon
* remaining ammunition

---

Slot 4

Current equipment.

Displays:

* icon
* remaining duration

---

### FPS Counter

Displayed beside the Settings button.

Purpose:

* communicate current FPS cap;
* reinforce the importance of FPS gameplay modifiers.

---

### Match Timer

Displayed at the bottom-center.

Counts total survival time.

Future boss encounters may reference this timer.

---

# 5.5 HUD Toggle

The HUD can be disabled after unlocking the corresponding configuration.

When disabled:

Hidden:

* HP bar
* XP bar
* inventory
* timer
* FPS counter

Visible:

* Settings button

The player must still be capable of pausing the game.

---

# 5.6 Pause Menu

Opening the Settings button pauses gameplay.

The Pause Menu contains:

* Resume
* Settings
* Return to Main Menu

No gameplay occurs while this menu is open.

---

# 5.7 Settings Menu

The Settings Menu is available:

* from Main Menu;
* during gameplay.

The same menu is reused.

Gameplay pauses automatically when opened in-game.

---

# 5.8 Settings Categories

Configurations should be grouped.

## Gameplay

Contains gameplay-affecting configurations.

Examples:

* FPS Cap
* Graphics Quality
* Resolution
* HUD
* Mouse Movement
* Enemy Ranged Attacks

---

## Controls

Contains:

* Keybinds
* Mouse options

---

## Audio

Contains:

* Master Volume
* Music Volume
* SFX Volume

---

## Graphics

Contains:

Visual-only options that do not influence gameplay.

Future additions may be placed here.

---

# 5.9 Locked Configurations

Locked gameplay configurations remain visible.

Appearance:

* darkened icon;
* disabled interaction;
* question mark overlay.

Purpose:

Show progression.

Players should always know additional configurations exist.

---

Each gameplay configuration includes a detailed information panel.

Contents:

Configuration Name

Description

Gameplay Effect

Difficulty Impact

Flavor Text

Example:

---

Every button should support:

Idle

Hover

Pressed

Disabled

# 5.12 Notifications

Short notifications appear when important events occur.

Examples:

Configuration Unlocked

Weapon Acquired

Equipment Equipped

Level Up

Future notifications:

Boss Incoming

New Enemy Type

Achievement

---

# 5.13 Level-Up Screen

When leveling up:

Gameplay pauses.

Screen darkens slightly.

Three randomly selected locked gameplay configurations appear.

Each card displays:

* icon
* name
* short description

Selecting one immediately unlocks it.

The menu then closes.

---

# 5.14 Configuration Cards

Configuration cards should resemble collectible upgrade cards rather than ordinary menu entries.

Each card contains:

Top

Configuration icon.

Center

Configuration name.

Bottom

Short description.

Corner

Difficulty indicator (optional).

Flavor text is intentionally hidden during selection to reduce clutter.

Players can read the full information later from the Settings Menu.

---

# 5.15 Inventory UI

Inventory icons should remain visually distinct.

Suggested icon language:

Slot 1

Wrench.

---

Slot 2

Pistol.

---

Slot 3

Current weapon sprite.

---

Slot 4

Current equipment sprite.

Equipment duration should be represented using:

* countdown text;
* shrinking timer bar;
* radial indicator.

Final choice determined during implementation.

Wooden crate.

Different colors.

Different icon.

Examples:

XP

Purple.

---

Healing

Red.

The cursor remains visible at all times.

Future improvements may include:

* weapon-specific cursor;
* reload animation;
* contextual highlights.

Primary colors:

Green

Health.

Yellow

Experience.

Purple

XP drops.

Orange

Equipment.

Red

Healing.

Locked configurations.

# 5.19 Accessibility

Current accessibility features:

* configurable keybinds;
* configurable audio levels;
* configurable resolution;
* adjustable FPS cap.

Future possibilities:

* colorblind palettes;
* UI scaling;
* larger fonts.

Accessibility options should never interfere with gameplay-affecting configurations unless intentionally designed to do so.

---

# 5.20 Sound Feedback

Every important interaction should produce immediate audio feedback.

Including:

Hover button

Click button

Pause

Resume

Configuration unlocked

Drop collected

Weapon replaced

Equipment replaced

Level Up

Player damaged

Player death

Audio reinforces responsiveness.

---

# 5.21 Error Prevention

Menus should prevent invalid actions.

Examples:

Cannot:

* enable locked configurations;
* equip nonexistent weapons;
* interact while another modal window is open.

Every unavailable option should clearly communicate why it is unavailable.

---

# 5.22 UX Philosophy

The UI should communicate two very different feelings.

During gameplay:

Fast.

Clean.

Readable.

During configuration:

Experimental.

Encouraging.

Curiosity-driven.

Players should frequently think:

> "I wonder what happens if I turn **this** on."

The Settings menu should feel less like a traditional options screen and more like a laboratory where the player deliberately engineers increasingly ridiculous gameplay combinations.

That feeling of experimentation is one of the game's defining UX goals.
